## 目标与边界

一次性配置后，用户仍只需点击原 Codex 图标、使用「退出 Codex」、再次打开。后台缺席时自动准备，已存在时复用；Desktop 真正退出后后台保留，重开并打开原聊天后可继续使用桌面工具和内置浏览器。

允许用户级服务、环境变量和外部适配器。不修改应用包、图标或签名，不伪造身份、不放宽安全校验。无需日常执行命令、使用替代图标或打开其他应用。自动选中上次聊天不属于本轮验收要求。

## 已验证的结构

```text
Desktop → 外部适配器 → 原装桌面工具及浏览器插件
                │                 ↑
                ↓                 │
          独立共享后台 → 工具代理 → 当前桌面桥接
```

Desktop 通过 `CODEX_CLI_PATH` 启动适配器，使用 `CODEX_APP_SERVER_FORCE_CLI=1` 并清除外部 WebSocket 覆盖。多个适配器各有独立 socket，连接同一后台；辅助 CLI 调用交回原版 CLI。插件由当前 Desktop 的后代进程启动，正常接受祖先链、签名和审批检查。

[参考 Gist](https://gist.github.com/ale-rinaldi/80f063b60177f1281e219ebd68587a4d) 的 `CODEX_APP_SERVER_WS_URL` 直连方案没有完成上述工具桥接，不作为本轮目标结构。

## 工程版最小验收

1. 用最终安装目录执行准备和启用，从原图标打开 Desktop，确认后台缺席时自动创建；实际调用只读桌面工具与 IAB 读取测试页标题。
2. 正常退出 Desktop，确认后台身份不变；再次从原图标打开原聊天，重复两类工具调用。
3. 正常退出后停用共享模式，从原图标恢复默认；核对环境与本组件生成的 CLI 路径恢复。

一次完整流程通过即可，不要求自动选中原聊天，不要求每项连续 3 次。原装 CUA 辅助后台不算重复聊天后台。工程版只做与迁移直接相关的隔离回归，不重复已完成的架构研究。

后续按实际需求补充：App/后台异常退出、在途任务跨退出、多聊天/第二客户端和压力测试。第二客户端在 Connector 接入时验证；这些未验证项需如实标注，但不阻塞当前工程集成。
