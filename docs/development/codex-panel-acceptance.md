# Codex 第二阶段验收

入口：当前安装的 LazyMind.app，沿用“Codex CDP 外部执行验收（临时）”。已有验收聊天也会自动显示 Panel，无需重新创建 Workflow。

1. 打开验收聊天，Panel 应在消息列表末尾、输入框上方。之前打开的右侧网页可以手动关闭。
2. 正常发送一条聊天消息，回复应出现在 Panel 前面；Panel 继续留在聊天末尾。
3. 收起、展开及放大 Panel，检查内容和编辑状态保持。无需重复开始 Workflow。
4. 上翻聊天历史，确认不会强行跳回底部、面板不会浮在历史消息上。回到底部后继续跟随。
5. 切到其他聊天，确认面板消失；切回验收聊天，应显示同一个 Workflow。
6. 在嵌入 Panel 中完成一次审核/继续，确认仍唤醒原聊天。可沿用第一阶段的停止窗口再做 Stop/恢复。
7. 在 LazyMind 关闭 Codex 开关，面板应移除；重新连接后恢复。Codex 应保持运行。
8. 同时打开主窗口和新窗口，各自进入已绑定 Workflow 的聊天，两边都应显示对应 Panel；关闭其中一个窗口后，另一个仍可操作。

## 普通重启后的恢复

CDP 是 Codex 的启动参数。从系统入口普通重开应用时，本机不会保留它。若面板消失，在 LazyMind 助理中点击 Codex 的“重新连接”，保存工作并按引导确认重启，再打开原聊天；不要重新创建 Workflow。

断线时助理会显示恢复提示，新建受控 Workflow 会先返回重新连接指引。已有 run 和审核结果仍保留，重新连接后恢复原绑定。

开发检查已确认：真实页面加载、末尾位置、同一个浏览器实例完成展开收起、上翻历史时隐藏容器，以及切换聊天后移除旧面板。测试未替用户提交审核或改变 Workflow 状态。

设计兼顾 Windows；当前仅完成 macOS 实机检查，Windows 未做实机验收。

## 操作区与统一交互

- 内置聊天与嵌入面板共用状态和按钮规则。等待审核时显示“继续执行”等审核按钮；执行中显示停止，失败显示重试，停止后显示继续，完成后按 Workflow 声明显示回退。
- 执行已让出、已有成功步骤且后续步骤可执行时，内外面板均显示继续按钮；正在自动运行时不显示继续。外部通知投递期间保留禁用状态，避免重复操作。
- 新聊天中的 MCP 提示词与其他外部 Agent 共用，不返回面板 URL，不引导打开浏览器。宿主会话识别留在接入层。

本轮统一范围：共用组件只读取统一的状态和操作能力，不判断 Provider 或内外执行身份。内部会话状态与 Core 控制快照在入口转换；操作分别通过聊天消息、Core 控制命令发送，权限和执行授权仍由后端校验。
